# README画像の更新

READMEの画像は撮影用Chromeで実画面を操作して生成します。画像の加工や版番号の手修正は不要です。製品のビルド・版情報と操作対象の識別子を使い、画像は同じファイル名で更新します。

## 準備

- Windows、Bun、インストール済みの依存関係が必要です。
- `bun run dev:setup`でChrome for TestingとTampermonkeyを用意します。準備済みの場合は再取得不要です。撮影コマンドは不足するブラウザ・拡張を自動ダウンロードしません。
- ポート9335を使います。手動用9333、自動検証用9334、普段のChromeやFirefoxは操作しません。
- 実サイトの動画は、対象と再生1回について利用者の承認を得てから撮影します。ログイン情報は引き継ぎません。投稿・タグ・マイリストの書き込み、実際の更新確認の実行はしません。

## 外部通信をしない予行

```powershell
bun run docs:screenshots --offline
```

既定もオフラインです。配布物をビルドし、既存の固定ページ・生成HLS・コメントで起動、再生、設定5カテゴリと右4タブの操作・撮影を確認します。Tampermonkeyの配布・導入・更新画像は実サイト撮影時にだけ生成します。予行の画像は`dev-assets/readme-capture/offline-<ID>/`へ保存し、README用画像を上書きしません。

予行では拡張機能を読み込まず、既存の通信遮断監視と禁止プロキシをブラウザ全体と専用コンテキストに使います。実サイトの撮影には禁止プロキシもシステムプロキシも使いません。

## 承認済みの実サイト撮影

```powershell
bun run docs:screenshots --live --attempt <承認した試行ID>
```

試行IDは英小文字・数字・ハイフンの4〜80文字です。開始前に`attempt-started.json`を排他的に作成し、中断・失敗しても同じIDでは再実行できません。新しいIDで再試行する場合も追加承認が必要です。既存の単発採取と同じ`monitorLiveRead`で、公式プレイヤー側の先行再生権要求、重複通信、書き込みを遮断します。

撮影の順序は次のとおりです。

1. `--no-proxy-server`付きで専用headless Chromeを起動し、実際の起動引数も確認します。毎回別のプロファイルを使います。
2. ChromeウェブストアのTampermonkey製品欄を撮影します。製品欄より上のブラウザ案内は切り出しに含めません。
3. ビルドした配布物をloopbackサーバーからTampermonkeyへ渡し、インストール確認画面を撮影します。公開リンクからのインストールと同じ配布物ですが、画像内の入手元はローカルURLです。専用プロファイルにだけ登録し、ダッシュボードで更新確認の選択画面を撮ります。「実行」は押しません。
4. 再生用には別の新規BrowserContextを作り、`proxyServer: direct://`を指定します。拡張の実行許可や導入状態の検証とは分け、配布物をページへ注入します。
5. `https://www.nicovideo.jp/watch/sm9`へ1回だけ遷移し、FWボタン周辺を切り出して撮影し、実クリックします。映像のデコード・時間進行・コメントCanvasの画素を確認してから再生場面を撮ります。
6. 同じページ内で設定5カテゴリと右4タブを実クリックし、表示状態を確認して撮影します。設定値は変更しません。右パネルの固定状態は撮影用コンテキストにだけ保存されます。
7. 全画像が揃い、監視の終了とブラウザ停止も成功した場合だけ、`docs/images/`へ画像15枚と`manifest.json`を出力します。失敗時には既存のREADME画像を上書きしません。

使い方の注釈は、実要素の位置を毎回測って撮影時だけ重ねます。注釈を除去してから次の操作へ進みます。UIの文字や版番号を撮影用に書き換えることはありません。Tampermonkeyの操作値や外部ページ構造が変わった場合は、実画面を調べてセレクターを更新してください。

## 確認と復旧

- 全画像を目視し、文字切れ・読み込み中・エラー・認証情報・NicoCacheの追加要素がないことを確認します。匿名の関連動画・コメントには第三者の公開コンテンツが含まれます。
- `manifest.json`には撮影した版、画面寸法、配布物と画像のSHA-256、実行した確認を記録します。ネットワーク記録・応答本文・失敗画像は`dev-assets/readme-capture/<試行ID>/`に置き、Gitへ追加しません。
- `bun run lint`、`bun run format`、`bun run type-check`、`bun run test`とオフライン予行を通します。CIも外部通信をしない予行を行います。
- 強制中断で専用Chromeが残った場合は`bun scripts/dev-browser.ts stop --screenshots`で停止します。停止対象は撮影用stateに記録したPIDだけです。
- 画像が不適切な場合は、公開前の差分を確認して画像とmanifestを直前のコミットへ戻します。実サイトの再撮影は承認後に行います。試行記録は消して再利用しません。
