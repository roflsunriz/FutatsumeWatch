# 実サイトを1操作だけ検証する

2026-09-20の利用者指定により、対象操作を1回だけ実行し、必要な関連通信を記録する。失敗後の追加操作・実通信は、別の承認があるまで行わない。今回は実サイトの読み取り再生が対象であり、公開投稿・タグ・マイリスト変更を含まない。

## 採取方法

- `scripts/dev-verify-live-once.ts`は専用Chrome 9334・隔離コンテキストで、sm9へ1回遷移し、可視の起動アイコンを1回クリックする。既存タブや実利用プロファイルを操作しない。配布物注入の確認であり、マネージャ経由ではない。
- Chrome自身の通信を送信前から監視し、要求メソッド・URL・本文・呼出元、応答ステータス・ヘッダー・本文、失敗理由、画面を保存する。HTML・API・HLSのテキストとバイナリを区別する。1応答8 MB・本文合計80 MBの上限超過や本文取得不能も明記し、記録から黙って落とさない。
- 許可するPOSTはsm9の再生権取得とコメント取得だけ。投稿等は遮断する。同じメソッド・正規化URL・本文・Rangeの再送を遮断し、認証値・試行番号の違いを再送許可に使わない。
- 公式プレイヤーが先に再生権を取得すると本体の初回が重複扱いになるため、採取後の修正版ではNetwork initiatorの`_createSession`を持つBlob Workerと、そのpreflightだけを再生権取得の対象にする。識別できない要求は許可しない。これは採取用の制限であり製品コードには入れない。
- Service Worker登録・WebSocket・beacon、無関係ホストは今回の対象外として遮断する。一般的な全通信キャプチャや、制約のない実サイト挙動の保証ではない。
- `attempt-started.json`を排他的に作成してから遷移する。同じ試行IDは再実行を拒否する。新しいIDを作ること自体を承認の代わりにしてはいけない。
- 証跡はGit管理外の`dev-assets/live-capture/<試行ID>/`へ保存する。認証ヘッダー・JSONキー・署名URLをマスクする。フィクスチャへ採用する前に、個人情報・認証値・再配布対象と形式を改めて確認する。

`bun scripts/dev-verify-live-once.ts --preflight`は外部サイトへ接続せず、専用ローカル応答で初回・503本文・Worker・重複／書込み遮断を確認する。実サイト用の新規試行は利用者の承認後にだけ実行する。

## 初回の結果

試行ID: `live-playback-sm9-2026-09-20-1`。操作は1回で終了し、実サイトへの再試行は行っていない。

- 起動導線の表示と実クリックは成功。HLSのデコード・時間進行は確認できず失敗した。
- 許可188件・遮断29件、要求記録229件、応答本文172件（約8.4 MB）、採取機構の例外0件。要求記録は複数sessionの観測を含むため、その件数を外部送信数と同一視しない。
- 公式ページ側で、再生権取得のPOSTが修飾なし／`__retry=0`付きで並行発生し、HTTP 201／200を受信した。両者とも本体クリック前の公式資産が呼出元だった。後者を別URLとして許可したため、初回の遮断判定は重複通信を完全には防げていない。この並行要求を失敗後の再試行だとは断定しない。
- その後のFutatsumeWatchの初回要求は、公式側と同じURLのOPTIONSを重複と扱ったため遮断された。画面は「動画の読み込みに失敗しました(domand) null」。検証側が本体の通信を止めた結果であり、製品故障や配信API拒否の証拠にはならない。
- TLSのissuerは`Adguard Personal CA`だった。OS側のHTTPS監視がある環境として記録し、介在のないサーバー通信と同一視しない。
- Cookie・認証キー等の自動マスクに加え、相対HLS URLも追加マスクした。初回採取時のスクリプトは同ディレクトリの`recorder-source/`へ保持した。

採取結果に基づき、`__retry`の正規化と公式／本体の要求分離を修正した。採取済みのinitiator形式による単体と、先行するページPOSTを遮断してWorkerのPOSTだけ1回通すローカルブラウザ検証は成功した。修正版の実サイトでの再検証は**未実行・追加承認待ち**。

ローカル確認の記録は`dev-assets/live-capture/preflight-1789914520359/`。同じ実試行IDを指定した拒否確認は`dev-assets/live-capture/consumed-id-check.log`で、ブラウザ起動前に終了した。採取時の配布物SHA-256は`d6e0655970d9698279c8a944c834be3c864b75ec1b1bbd80d4a1fb5740d0efff`。

## 次の試行で確認する条件

同じsm9の起動操作1回に限定し、公式側の再生権取得は外へ出さず、本体Workerの初回OPTIONS／POSTを記録する。本体POSTが1回だけ送信され、返されたHLSのデコード・時刻進行・コメント描画へ至るかを確認する。失敗時は新しい通信を足さず、その試行の記録で原因を調べる。
