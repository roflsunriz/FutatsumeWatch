# 実サイトを1操作だけ検証する

2026-09-20の利用者指定により、対象操作を1回だけ実行し、必要な関連通信を記録する。失敗後の再試行は、別の承認があるまで行わない。初回は読み取り再生のみ。その後、利用者が公開投稿・タグ編集・マイリストの作成と追加・削除を承認し、新着動画と内容の選定を委任した。以下では各試行を分けて記録する。

## 採取方法

- `scripts/dev-verify-live-once.ts`は専用Chrome 9334・隔離コンテキストで、sm9へ1回遷移し、可視の起動アイコンを1回クリックする。既存タブや実利用プロファイルを操作しない。配布物注入の確認であり、マネージャ経由ではない。
- Chrome自身の通信を送信前から監視し、要求メソッド・URL・本文・呼出元、応答ステータス・ヘッダー・本文、失敗理由、画面を保存する。HTML・API・HLSのテキストとバイナリを区別する。1応答8 MB・本文合計80 MBの上限超過や本文取得不能も明記し、記録から黙って落とさない。
- 許可するPOSTはsm9の再生権取得とコメント取得だけ。投稿等は遮断する。同じメソッド・正規化URL・本文・Rangeの再送を遮断し、認証値・試行番号の違いを再送許可に使わない。
- 公式プレイヤーが先に再生権を取得すると本体の初回が重複扱いになるため、採取後の修正版ではNetwork initiatorの`_createSession`を持つBlob Workerと、そのpreflightだけを再生権取得の対象にする。識別できない要求は許可しない。これは採取用の制限であり製品コードには入れない。
- Service Worker登録・WebSocket・beacon、無関係ホストは今回の対象外として遮断する。一般的な全通信キャプチャや、制約のない実サイト挙動の保証ではない。
- `attempt-started.json`を排他的に作成してから遷移する。同じ試行IDは再実行を拒否する。新しいIDを作ること自体を承認の代わりにしてはいけない。
- 証跡はGit管理外の`dev-assets/live-capture/<試行ID>/`へ保存する。認証ヘッダー・JSONキー・署名URLをマスクする。フィクスチャへ採用する前に、個人情報・認証値・再配布対象と形式を改めて確認する。

`bun scripts/dev-verify-live-once.ts --preflight`は外部サイトへ接続せず、専用ローカル応答で初回・503本文・Worker・重複／書込み遮断を確認する。実サイト用の新規試行は利用者の承認後にだけ実行する。

### 製品修正と証跡の制約

- 実ページの初期化時にCommonHeaderもserver-responseもなく、取得済みviewerはログイン済みなのに投稿欄がguestのままだった。`nicoUtil`は現在の動画要求のviewerを優先し、入力欄・一般会員状態・外枠のguest表示へ取得後に反映する。切替・closeで破棄し、古い応答を拒否する。
- 追加の再生・再読込を避け、実測中は修正ソースから生成した判定・表示メソッドを既存インスタンスへ適用した。認証値を偽装せず、実API viewerを使った。公開投稿等はこの適用後の結果であり、修正後の全配布物を新規文書で検証した結果とは呼ばない。最終配布物はヘッダー不在のオフラインブラウザケースで別途検証した。
- 証跡は`dev-assets/live-account/session-2026-09-21-1/`。`network.jsonl`が連続した要求・応答の記録、`actions.jsonl`が操作記録。書込み許可消費は作成・コメント・タグ・追加・リスト削除が各1回、項目削除は0回。公開操作の再送はない。
- 書込み開始前の採取プロセス再開で本文連番が衝突し、以前の4応答本文を失った。要求・ステータスは保持され、公開操作の応答本文は残る。`body-index.json`は観測ID・時刻ごとの実ファイルと欠損を示す。`body-relocations.json`と退避先`bodies-before-public-writes/`も参照する。退避先の名称に反して、リスト作成の応答も含む。欠損を補うための再取得は行っていない。
- 今後の本文名には採取プロセスごとのUUIDを含める。認証ヘッダー・キー・署名URLだけでなく、CDPのbase64本文副本`postDataEntries`とアカウントIDヘッダーもマスクし、今回のJSON記録へも適用した。証跡・本人プロファイルはGitへ含めない。
- タグの成功、個別項目削除、削除後一覧、投稿後再取得の追加実測には新たな承認が必要。失敗した操作を新しいIDで自動再実行しない。

### 書込み採取の制御

`scripts/live-write-permit.ts`は対象動画・本文・タグ・mylist ID・item IDとメソッド／パス／本文を厳密照合し、各種類の許可を送信前に1回だけ消費する。成否不明や失敗でも再利用できない。同じ実行で作成・追加の成功を確認したIDだけを削除対象へ登録できる。公式作成APIのformには名前・説明・非公開指定・既定の並び順2項目が必要。

`scripts/dev-live-account-session.ts --session <承認済み試行ID>`は本人ログインを済ませた専用9341の`dev-assets/live-account/state.json`を前提とする対話式コントローラー。入力・実クリック・読取・対象別許可・成功IDの登録をJSON行で記録する。通常テストやCIから起動しない。`--resume`は書込み許可消費前だけで、読取履歴と操作IDを復元する。終了時は専用コンテキスト全体を破棄する。

関連GETの明示許可はそのGETと必要なOPTIONSを各1回だけ通す。今回の削除後照会で見つかったOPTIONS遮断はローカル単体で修正したが、実サーバーへの再照会は行っていない。ローカル採取検証`preflight-1789921223003`は6項目成功。
